# CDT501 · F2 — Permission-enforced document agents

Research prototype for the question: **can a document agent contain malicious instructions hidden
in documents and still finish legitimate work?**

> Status: under construction (phase-by-phase, see `docs/plan.md`). All results are `TBD` until
> produced by a committed command into `results/`.

## Quick start
```bash
git clone https://github.com/irenasikia-svg/cdt501-f2
cd cdt501-f2
uv sync
bash scripts/check.sh
```
Real-LLM runs need a `.env` (copy `.env.example`). Development and `check.sh` use deterministic
mock models only and need no key.

## Method (summary)
A trusted user task is turned into a **capability manifest**. Every tool call the agent proposes is
checked in Python by a **policy engine** (tool allowlist, typed argument checks, information-flow
rule, read-only by default) before it reaches a simulated sink. All decisions go to an audit log.
Details: `docs/architecture.md` (TBD, P8).

## Data
| split | content | written by |
|---|---|---|
| `data/benign/tasks.json` | 40 legitimate tasks (summarise, answer, email, search, fetch, combine, delete), each with a deterministic state-based checker and trusted capabilities | generated by `scripts/build_dev_data.py` |
| `data/dev_attacks/attacks.json` | 35 attacks = 5 dev families × 7 goals, each riding on a benign task | generated by `scripts/build_dev_data.py` |
| `data/heldout/` | held-out attacks from 5 *different* families (see its README) | human team only |

Splits are by **attack family**, not random examples. `data/MANIFEST.sha256` freezes all three;
`scripts/check.sh` fails if any frozen file changes.

## Results
All numbers live in `results/` and are regenerated by `scripts/run_eval.py`:
`summary.csv` (per run × split × condition), `family_breakdown.csv`, `figures/`, and
`failures_C2.md` (every attack that succeeded under C2, with its audit log). Mock-model runs are
in; real-LLM results are TBD (pending a confirmed run). Run history: `docs/experiment_log.md`.
